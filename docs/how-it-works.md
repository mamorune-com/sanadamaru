# 仕組み

真田丸の本体は `Castle.check`（[python/sanadamaru/castle.py](../python/sanadamaru/castle.py)）です。FastAPI・Flask などへのつなぎ（`asgi.py`・`wsgi.py`）は、問い合わせを `Castle.check` に渡すだけです。

## 見る順番

`Castle.check` は、1つの問い合わせを、次の順に見ます。

1. **締め出し中か**（締め出しがオンの時だけ）。締め出し中なら 403 を返します。止めない窓口（`never_block`）は見ません。
2. **偽の扉か**。扉なら、作り物の中身を 200 で返し、記録します。
3. **偽の鍵が出されたか**。出されたら、記録して 403 を返します。止めない窓口では、記録だけして通します。
4. どれでもなければ、何もせずに本物の窓口へ通します（`None` を返します）。

## 偽の扉

- 住所は、そろえてから比べます。`//` は `/` に、最後の `/` は取ります。大文字と小文字は区別します。
- 中身は、起動の時に1回だけ作り、毎回同じものを返します。本物の設定ファイルは、開くたびには変わらないからです。
- 返す見出しは `Content-Type`・`X-Content-Type-Options: nosniff`・`Cache-Control: no-store` です。途中の仕組みに中身を覚えられると、2回目からの探りが記録に届かなくなるため、覚えさせません。
- HEAD には中身を付けず、長さだけを返します。
- 扉は、どの方法（GET・POST など）で来ても扉です。

## 目印入りの偽の鍵

```text
偽の鍵 = 書き出し（key_prefix） + HMAC-SHA256(secret, "sanadamaru/v1" ‖ 目印 ‖ 欄) の先頭32文字（16進）
```

- 同じ secret・目印・欄なら、いつも同じ鍵になります。secret が違えば、別の鍵になります（導入ごとに違う鍵）。
- 鍵の中に、目印や欄はそのまま書かれていません。相手は、鍵を見ても、どの扉のものか分かりません。
- 照らし合わせは、作った鍵の一覧と、そのまま比べます。書き出しが同じでも、一覧に無い鍵は偽の鍵とみなしません。
- 探す場所は、`Authorization`（Bearer と、Basic の合言葉）・`X-API-Key`・`X-Admin-Key`・`X-Auth-Token`・`X-Access-Token`・`?` より後ろです。本文は読みません。1つの値で探す長さには上限があります。
- 扉の外に置く鍵も、`castle.bait_key("目印", "欄")` で作れます。偽の書類などに置いておけば、使われた時に気づけます。

## 送り元の読み方

| `client_ip` | 読む所 | 使う時 |
|---|---|---|
| `direct` | 直接つないできた相手 | 前に何も立っていない時 |
| `cloudflare` | `CF-Connecting-IP`（Cloudflare が上書きします） | Cloudflare を通らないと届かない構成（Render など） |
| `x-forwarded-for` | `X-Forwarded-For` の右から `trusted_hops` 番目 | ロードバランサーなどが前に立つ時 |

- 読めない時は、直接つないできた相手の番号を使います。それも読めなければ、空にします。
- `X-Forwarded-For` の左側は、呼び手が自由に書けるので、決して使いません。

## 締め出し

- 期限があります（既定は24時間）。期限が来たら、自動で解けます。
- 締め出しておける番号の数に、上限があります（既定は1万）。番号を変えて大量に来ても、メモリを食いつぶしません。
- 締め出さない番号：Cloudflare 自身の番号・公開されていない番号（社内・家庭内・CGNAT・ループバック・説明用の番号など）・読めない番号。

## 記録と知らせ

`castle.report()` は、次を返します。

| 名前 | 中身 |
|---|---|
| `total` | 起動してからの、扉と偽の鍵の回数 |
| `by_door` | 扉ごとの回数 |
| `bait_key_by_marker` | 目印ごとの、偽の鍵が使われた回数 |
| `sources` | 最近の記録にある送り元の数 |
| `banned_now`・`blocked` | 締め出し中の数と、締め出しで断った回数 |
| `recent` | 最近の50件（新しい順） |

- 記録の1件は、時刻・種類・方法・住所・目印・欄・送り元の番号と頭・UA の頭・締め出したか、です。
- 記録の行（`logging` の WARNING）には、送り元の番号の頭だけを出します。
- 知らせ（`alert`）は、同じ種類と目印につき、`alert_cooldown` 秒（既定は1時間）に1回までです。知らせに渡す中身には、送り元の番号の頭だけが入ります。知らせが失敗しても、守りは止まりません。

## 複数のプロセス・サーバー

記録と締め出しは、プロセスごとのメモリにあります。プロセスやサーバーが複数ある時は、それぞれが別に記録し、別に締め出します。偽の鍵は secret から作るので、どのプロセスでも同じ鍵になり、どこで使われても気づけます。

## 別の言語に移す時

Express・Go・Rails などに移す時は、次をそろえてください。

- 見る順番（上の1〜4）
- 偽の鍵の作り方（同じ secret・目印・欄なら、同じ鍵になること）
- 送り元の読み方と、締め出さない番号
- 制御文字の置き換えと、記録の上限
- [越えない線](lines.md)

[python/tests/](../python/tests/) のテストを、移した先のテストの手本にしてください。
